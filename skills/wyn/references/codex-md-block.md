# What You Need (WYN)

Before acting, briefly consider whether a better tool would make the next job faster, more efficient, or produce a better result. Keep this WYN habit active throughout the task, even when the current approach works. Reuse or switch to existing capabilities, including tools in `~/wyn/README.md`, or obtain, adapt, compose, or build what is needed. Keep the check lightweight; investigate when the likely benefit earns the cost.

Use the `wyn` skill at `{{skill_path}}` when applying this approach. Do not wait for a blocker or an explicit request. Missing tools, installs that appear to need sudo, repetitive work, and CLI worker coordination are additional triggers. Load it before declaring a task blocked by missing tooling.

Use explicit CLI processes and interactive tmux sessions within the task's scope and budget. Avoid built-in subagent delegation. Use existing authorized authentication and follow account and spending policies.

Use economical models for doing, a middle tier for hard work, and a stronger model for bounded verification. Tune reasoning effort separately. Report with `WYN:` and name relevant paths, folders, and files.

Choose a suitable language for the task. Read `~/wyn/README.md` before creating reusable tooling, prefer projects under `~/wyn/`, and keep the index current. Offer mature tools for publication and maintain published projects according to their recorded authorization.
